## 2. 기술 스택

- **엔진**: Unreal Engine 5.8, C++ 중심 (BP는 에셋 연결·연출)
- **게임플레이**: GAS 어트리뷰트 계층(체력·마나 복제/변경 알림), 자체 StatComponent(태그 기반 스탯·모디파이어), 데이터 테이블 기반 스킬·아이템·몬스터
- **AI**: 필드 몬스터 FSM(AIController), 보스 Behavior Tree + Blackboard
- **네트워크**: 서버 권한, Server RPC / Multicast RPC / 복제 프로퍼티 역할 분리, 파티 단위 보스방 인스턴싱
- **UI**: CommonUI 기반 위젯, 타이포그래피 테마, MVVM 일부
- **데이터**: Google Sheets → CSV → DataTable 파이프라인(에디터 모듈)
- **백엔드**: Rust Axum, sqlx, PostgreSQL, Docker Compose
- **협업**: GitHub Flow(기능 브랜치 → `dev` PR → `main`), Git LFS, Sourcetree

## 4. 아키텍처 요점

```
[클라이언트] 입력 ─Server RPC→ [데디 서버] 판정·피해·AI·스폰·존 이동
                                   │  복제 프로퍼티(체력·페이즈·존) / Multicast(연출)
[클라이언트] 위젯·데칼·VFX ←────────┘
                                   │  HTTP(JSON)
                              [Rust API] ── PostgreSQL (계정·캐릭터·세이브)
```

- **판정은 서버만**: 피해·사망·보상·스폰·방 배정은 전부 `HasAuthority()` 경로.
- **필드는 공용, 보스방은 파티 인스턴스**: 별도 레벨이 아니라 같은 맵의 방 4개를 서버가 파티 단위로 배정(빈 방 우선, 파티원 합류, 재입장 차단).
- **데이터 주도**: 몬스터·스킬·아이템·보스 패턴이 전부 표/배열. 기획 수치 변경에 코드 수정이 필요 없음.

## 5. 결과와 한계

**된 것**
- 로그인 → 캐릭터 선택 → 필드 사냥 → 성장·장신구 → 파티 → 보스방 배정 → 보스 2종 레이드까지 한 사이클이 서버-클라 구조로 동작
- 패키징 빌드 + 원격 데디 서버 접속 시연

**아쉬운 것 / 다음**
- 방어 공식 상수가 작아 직업 간 피해 격차가 큼(임시로 방어 성장 제거)
- 늦게 합류한 클라이언트는 진행 중인 원샷 연출(예고·VFX)을 못 봄
- 내비메시는 통짜 굽기. 맵이 더 커지면 World Partition 내비 조각으로 전환 필요
- 로그인 화면과 서버 주소 선택이 분리돼 있음(접속 주소는 실행 인자)
